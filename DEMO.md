# Demo Guide

This guide covers exact setup and run commands, sample questions, how to show each
technology, test/evaluation commands, a 5-10 minute demo script and troubleshooting.
All commands are for **Windows PowerShell**, run from the project folder.

---

## 1. Setup (one time, ~10 minutes, mostly model download)

### 1.1 Ollama (native Windows, the primary setup)

```powershell
winget install Ollama.Ollama        # or download from https://ollama.com/download/windows
ollama pull llama3.2:3b             # chat model, ~2.0 GB
ollama pull nomic-embed-text        # embedding model, ~270 MB
ollama list                         # both models should be listed
```

The Ollama app starts automatically and runs in the system tray (API on `http://localhost:11434`).
If it isn't running, start it from the Start menu or run `ollama serve`.

### 1.2 Python environment (Python 3.11, 3.12 or 3.13)

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -e . --no-deps
copy .env.example .env
```

### 1.3 Verify

```powershell
docqa doctor        # prints settings and "All good." when Ollama and both models are available
pytest              # 43 passed + 1 skipped without Ollama (~20 s); 44 passed once Ollama + models are up (~40 s)
```

## 2. Run

```powershell
streamlit run app.py
```

Open **http://localhost:8501**. On first load the app starts the MCP document server as a
subprocess, which takes a few seconds.

Reset everything (index, memory, traces, reports): stop the app and delete the `data\` folder.

## 3. Sample documents and questions

`demo_data/docs/` contains four documents about a fictional company, *Nimbus Labs*:

| File | Type | Content |
|---|---|---|
| `employee_handbook.md` | Markdown | hours, remote work, PTO, parental leave, learning budget, expenses |
| `product_faq.txt` | Text | Nimbus Notes plans & prices, trial, refunds, offline mode, support |
| `security_policy.pdf` | PDF (2 pages) | passwords, API key rotation, incident reporting, data classes |
| `release_notes.md` | Markdown | versions 2.0-2.3, API v1 deprecation |

(The PDF is generated by `python scripts/make_sample_pdf.py`, so it contains real, extractable text.)

**Good questions**

| Question | Expected answer | Shows |
|---|---|---|
| How many days of PTO do employees get? | 25 days per year | basic RAG + citation |
| → *Can I carry any of them over to next year?* | Up to 5 days, the rest expire 31 March | **memory** (rewritten to "Can 25 days of paid time off be carried over…") |
| How often must API keys be rotated? | At least every 90 days | answer from the **PDF** (page citation) |
| When will the legacy REST API v1 be shut down? | 31 December 2026 | release notes |
| How much does the Pro plan cost? → *And how much storage does it include per user?* | 12 USD/user/month → 100 GB | **memory** |
| What is the weather in Paris today? | declined | **refuse** route: no chunk passes the cutoff, no LLM call |
| What is the stock price of Nimbus Labs? | declined | chunks look relevant but the LLM returns `found=false` |

The evaluation set is `demo_data/eval/eval_set.jsonl`: 15 questions, including 2 unanswerable
questions and 1 memory follow-up.

## 4. What to show for each technology

| Technology | Where to show it |
|---|---|
| **LangGraph** | **LangGraph trace** tab: the workflow graph with the route actually taken highlighted in green, a table of node spans, and the Mermaid source from `graph.get_graph().draw_mermaid()`. Compare an answered question (`…generate → validate`) with an off-topic one (`…grade → refuse`). Code: `src/docqa/graph.py`. |
| **MCP** | **MCP tools** tab: the 5 tools and their JSON input schemas, as listed by the server. Call `search_documents` by hand. Every retrieval in the trace shows `tool: mcp:search_documents`. The server runs on its own: `python -m docqa.mcp_server`. Code: `mcp_server.py`, `mcp_client.py`. |
| **Pydantic** | In the MCP tools tab, call `search_documents` with `{"query": "refund", "top_k": 99}`: the server rejects it (`top_k: Input should be less than or equal to 20`). Other examples are the `LLMAnswer` schema sent to Ollama as JSON schema (`models.py`), the validate node and its retry (`pytest tests/test_graph.py -k retried`), and settings validation (set `DOCQA_TOP_K=0` and run `docqa doctor`). |
| **Ollama** | Sidebar shows 🟢 for both local models. Token counts per node in the trace tab. The only network calls go to `localhost:11434`. |
| **Memory** | Sidebar: "N turns stored for `demo`". Ask a follow-up, and the chat shows *🧠 memory rewrite: …*. Restart Streamlit and the conversation is still there (SQLite checkpointer, `data/memory.sqlite`). **New chat** switches thread (empty memory); typing the old thread id brings it back. |
| **Evaluation** | **Evaluation** tab: **Run evaluation** (about 3 min for 15 questions on CPU; tick LLM-as-judge for a 1-5 grade). Shows metrics plus a per-question table. Reports are saved in `data/eval_reports/` as JSON and Markdown. |
| **Observability** | **Observability** tab: request count, average/p95 latency, not-found rate, errors/retries, token totals, average time per node, latency over time, recent traces. Raw data is in `data/traces.jsonl` (download button), also available as `docqa traces`. |

## 5. Demo flow (about 8 minutes)

| Time | Step | What to say / show |
|---|---|---|
| 0:00 | **Intro** (README architecture diagram) | "Everything runs locally: Ollama for the models, an MCP server for documents, a LangGraph workflow, a Streamlit UI. No cloud, no paid APIs." |
| 0:45 | **Load documents**: sidebar → *Load demo docs* (or upload a PDF/TXT/MD) | The four docs appear with chunk counts. "Ingestion went through the MCP `ingest_document` tool: load → chunk → embed with `nomic-embed-text` → NumPy index." |
| 1:30 | **Ask**: *How many days of PTO do employees get?* | Answer + confidence + **Sources** expander (file, chunk, similarity). |
| 2:15 | **Memory**: *Can I carry any of them over to next year?* | The chat shows the memory rewrite ("Can 25 days of paid time off be carried over…"). Sidebar counter goes to 2 turns. |
| 3:00 | **LangGraph trace** tab | Highlighted path, per-node latency, the `retrieve` span showing the MCP tool call and scores, the `contextualize` span showing the rewrite. |
| 3:45 | **Refusal**: *What is the weather in Paris today?* | Route `grade → refuse`, no LLM call, about 3 s. Then *What is the stock price of Nimbus Labs?*: retrieved, but the model answers `found=false` ("I don't know…"). "Two layers against hallucination." |
| 4:45 | **MCP tools** tab | List of tools with schemas. Call `search_documents` with `{"query": "refund policy", "top_k": 3}`, then with `top_k: 99` to show Pydantic validation at the MCP boundary. |
| 5:45 | **Evaluation** tab | Show the latest report, or run it with **Questions to run = 5** to keep it short (~1 min). Explain the metrics: retrieval hit, citation accuracy, keyword score, refusal accuracy, judge. |
| 7:00 | **Observability** tab | Latency, per-node time (generation dominates), tokens, recent traces, `traces.jsonl`. |
| 7:45 | **Persistence** (optional) | Stop and restart `streamlit run app.py`. The thread `demo` still has its history. |
| 8:15 | **Tests** (optional, terminal) | `pytest`: 43 tests run with a fake LLM (including a real MCP subprocess and a Streamlit UI test), plus 1 live Ollama test. |

Tip: run the full evaluation once **before** the demo so the Evaluation tab already shows a
complete report, then run only 5 questions live.

## 6. Tests and evaluation commands

```powershell
pytest                                   # all tests with the fake LLM (no Ollama needed)
pytest -v tests/test_mcp.py              # MCP server over real stdio
pytest -v tests/test_graph.py            # LangGraph routing, retry, memory, tracing
pytest -v tests/test_e2e.py              # CLI + Streamlit AppTest + full pipeline over MCP
pytest -m ollama                         # live end-to-end test against Ollama (~40 s)

docqa eval                               # 15 questions with the real models, report in data/eval_reports/
docqa eval --judge                       # + LLM-as-judge (1-5)
docqa eval --limit 5                     # quick run
python scripts/run_eval.py --judge       # same, as a script

docqa ingest; docqa docs                 # debug CLI: ingest demo docs, list them
docqa ask "How often must API keys be rotated?" --thread t1
docqa chat --thread t1                   # interactive, /history /clear /exit
docqa traces --last 10                   # recent traces + aggregate metrics
docqa graph                              # Mermaid diagram of the workflow
```

**Reference results** (measured on this machine: Windows 10, CPU only, `llama3.2:3b` +
`nomic-embed-text`, `DOCQA_MIN_SCORE=0.55`):

| Metric | Value |
|---|---|
| Accuracy | 100 % (15/15) |
| Retrieval hit rate | 100 % |
| Citation accuracy | 92 % (q12: correct answer, but the 3B model cited passage [2] instead of [1], visible in the trace's `validate` span) |
| Refusal accuracy | 100 % (2/2) |
| Mean keyword score | 1.0 |
| LLM-as-judge | 5.0 / 5 |
| Avg latency | ~6-13 s per question (CPU); ~3 s for refused questions |

A small model can vary between runs, so expect small differences.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| Sidebar: *Ollama not reachable* | Start the Ollama app (tray icon) or run `ollama serve`. Check with `curl http://localhost:11434/api/version`. If you use another host or port, set `DOCQA_OLLAMA_HOST` in `.env`. |
| 🔴 model in sidebar / `docqa doctor` fails | `ollama pull llama3.2:3b` and `ollama pull nomic-embed-text`. The model names in `.env` must match `ollama list`. |
| `ollama` not recognized after installing | Open a new terminal (PATH is updated on install), or use `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`. |
| `Activate.ps1 cannot be loaded because running scripts is disabled` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, or call tools directly: `.\.venv\Scripts\streamlit run app.py`. |
| pip fails to build packages / Python 3.14 | Use Python 3.11-3.13 (`py -3.13 -m venv .venv`). Some dependencies don't have 3.14 wheels yet. |
| `ModuleNotFoundError: docqa` | Activate the venv and run `pip install -e . --no-deps` from the project folder. |
| Very slow answers (>30 s) | CPU inference; the first question also loads the model into RAM. Close heavy apps, keep `llama3.2:3b`, or reduce `DOCQA_TOP_K` to 3. An NVIDIA GPU is used automatically by native Ollama. |
| Assistant refuses questions it should answer | Lower `DOCQA_MIN_SCORE` (e.g. 0.5). The **LangGraph trace** tab shows each chunk's score and whether it was kept. |
| `Embedding dimension changed` error | You switched `DOCQA_EMBED_MODEL`. Delete `data\index` and re-ingest. |
| Uploaded PDF gives "No extractable text" | It is a scanned (image) PDF; OCR is not supported. |
| Port 8501 already in use | `streamlit run app.py --server.port 8502`, or close the other Streamlit instance. |
| Old conversation or eval results clutter the demo | Stop the app and delete `data\` (or just `data\memory.sqlite` / `data\traces.jsonl`). |
| Docker: app can't reach native Ollama | `docker compose up` uses `http://host.docker.internal:11434`. Make sure Docker Desktop is running and Ollama is up on the host. |
| Docker: fully containerised fallback | `docker compose --profile ollama up --build`, set `DOCQA_OLLAMA_HOST=http://ollama:11434`, then `docker compose exec ollama ollama pull llama3.2:3b` (and `nomic-embed-text`). CPU only, slower. |
